## Data Flow

### Flow 1: Candidate Intake & Project Submission
1. **Intake**: Candidate registers via WhatsApp or web portal; record is created in MongoDB (`Candidate`).
2. **Project Submission**: Candidate enters GitHub URL via `/api/student/project/submit`.
3. **Verification Engine**: Backend GitHub client fetches file trees and key files (commits, package configs, source files).
4. **AI Analysis**: Groq LLM evaluates repository complexity, commit patterns, and authorship authenticity against project specs.
5. **Outcome**: Project marked `VERIFIED`, `REJECTED`, or `NEEDS_ADMIN_REVIEW`.

### Flow 2: Interview Scheduling & Calendar Integration
1. **Slot Selection**: Candidate accesses available slots at `/api/student/interview/slots`.
2. **Booking**: Concurrency-safe booking writes `Interview` and updates slot state in MongoDB.
3. **Calendar Sync**: Backend calls Google Calendar API using stored OAuth refresh tokens (AES-256 decrypted) to create a Google Meet meeting event with candidate and bot as attendees.
4. **Notification**: Confirmation emails/WhatsApp messages dispatched with Meet URL and time.

### Flow 3: Live AI Voice Interview Execution
1. **Job Dispatch**: Distributed bot worker leases scheduled interview job from `/api/bot-control/jobs/acquire`.
2. **Meeting Join**: Playwright opens Chromium with persistent profile, navigates to Meet URL, clicks "Join", selects VB-Audio Cable devices.
3. **Audio Capture & STT**: WASAPI loopback captures candidate audio; Deepgram Nova-2 transcribes speech to text in real time.
4. **Dialogue & Scoring**: STT transcript is posted to `/api/ai-interviews/:id/answers`; RecruitAI evaluates response, updates rubric, and returns next question.
5. **TTS Synthesis**: Kokoro TTS synthesizes bot voice audio and streams it into Google Meet microphone input.
6. **Session Finalization**: When interview completes or time limit expires, backend generates detailed evaluation report with scores, strengths, weaknesses, and admin recommendation.

## Conventions

**Naming:**
- Backend files use descriptive dot notation: `<domain>.<role>.js` (e.g., `interview.model.js`, `interview.routes.js`, `interview.service.js`).
- Test files use `.test.cjs` for Jest CommonJS tests in ESM package, and `.test.ts` for frontend TypeScript tests.
- React components use PascalCase (`CandidateTable.tsx`, `InterviewRoom.tsx`).
- Python files follow snake_case naming (`audio_capture.py`, `kokoro_tts.py`).

**Structure:**
- Backend features organized into domain modules in `backend/src/modules/<feature>/`.
- Frontend utilizes Next.js 14 App Router hierarchy with route groups (`app/admin`, `app/student`, `app/api`).
- Reusable UI elements strictly separated in `frontend/components/`.

**Testing:**
- Backend: Jest unit and integration tests (`npm test` in `backend/`), running in-band with mocked external APIs.
- Meeting Bot: Pytest suite (`.venv\Scripts\python.exe -m pytest tests`), comprehensive unit coverage for admission, audio, dialogue flow, and bot worker.
